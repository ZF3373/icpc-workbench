## 3. 改动项清单（按优先级）

### 高优先级（P0）——控制台信号可信 + 无障碍补口

#### H1 · Calendar 弃用 API 改名
- **问题**：`dateFullCellRender` 已弃用，每次进入日历页产生一条控制台告警。
- **建议**：`Calendar.tsx:236` 改为 `fullCellRender`。注意 `fullCellRender` 接收完整单元格（含日期），现有 `renderCell` 返回结构需对齐（官方迁移为改名 + 包一层 `<div className="ant-picker-cell-inner">` 视觉对齐，以实测渲染为准）。
- **预期效果**：日历页控制台告警清零；渲染外观不变。
- **成本**：0.5 小时（含回归截图）。

#### H2 · `useForm` 未连接告警清零
- **问题**：见 I2。两处瞬时告警，非功能缺陷，但污染控制台。
- **建议**：
  1. `ImportPlanModal` 的 `<Modal>` 加 `forceRender`（一行，强制提前挂载 Form，代价仅是设置页多渲染一个隐藏表单）；
  2. `aiForm` 的告警根治方案是**AI 配置表单拆为子组件**（form 实例移入子组件，子组件在数据就绪后才 mount）——若不想动结构，可短期接受该条告警并在 `:174` 加注释说明根因，避免后人再当真缺陷排查一遍。
- **预期效果**：控制台归零（或仅剩一条有注释的已知项），错误信号恢复可信；顺带为 L1 的组件化铺路。
- **成本**：方案一 0.5 小时；方案二（含子组件拆分）0.5 天。

#### H3 · 会话重命名补键盘路径（新发现）
- **问题**：见 I1。键盘用户无法重命名会话；触屏设备同样不可达。
- **建议**：会话行 hover 操作区（与既有上移/下移 `.reorder-controls` 同位）增加显式「重命名」按钮，点击进入既有 `renamingId` 编辑态；`title` 属性换 antd `Tooltip`（键盘聚焦即显示）。**不要**给行加 `tabIndex` + Enter 触发双击语义——行本身已是切换会话的按钮，语义冲突。
- **实际落地**：会话行已改为「拖拽手柄 + `⋯ 会话操作` 下拉菜单（重命名/置顶/删除）」+ 标题 `Tooltip`。
  重命名由该菜单承担：Tab 可达触发按钮 → Enter 打开菜单 → 选「重命名」→ 原地编辑 → Enter 提交。
  行内不再常驻 ↑↓ 按钮（拖拽与之重复）。详见 §5.4 第 4 条。
- **预期效果**：Tab 即可达重命名；可发现性不再依赖悬停；与全站「拖拽有键盘替代」的标准对齐。
- **成本**：0.5～1 天（注意与拖拽、键盘排序的 Tab 顺序回归）。
- **状态**：**已完成**（键盘路径实测可用；键盘排序按钮已从会话行移除，改由拖拽 + 此菜单承载，见 §5.4）。

### 中优先级（P1）——一致性收口

#### M1 · 清理 720px 遗留断点
- **问题**：见 R1。721–768 区间行为与全站 768 口径不一致。
- **建议**：先确认 `.card-actions-row`（≤768 已覆盖 Reviews / Plans）确实覆盖 `.review-item` 场景，确认后删除 `index.css:2335–2339` 整条规则；若未完全覆盖，把 720 改成 768 并合并语义。同步更新 `responsive-breakpoints.md` §0 / §4.1。
- **预期效果**：断点数值口径唯一（§0 总表去掉 720 行），721–768 区间卡片操作组正确下沉。
- **成本**：0.5 天（含 721–768 区间逐页回归）。

#### M2 · 排序按钮扩大命中区至 ≥24×24
- **问题**：见 U1。
- **建议**：**视觉尺寸不变，扩大命中区**——用 `::before` 伪元素撑出命中区（`.reorder-btn::before { content: ''; position: absolute; inset: -4px; }`），或直接放宽到 24×24 并微调间距。四处覆盖样式（`index.css:390 / 1086 / 3225 / 3407`）统一处理，避免只改一处造成新的不一致。
- **预期效果**：全部排序按钮命中区 ≥24×24；视觉密度无明显变化。
- **成本**：0.5 天（四处样式 + 五处列表页回归）。

#### M3 · `InputNumber addonAfter` → `Space.Compact`
- **问题**：见 V1，6 处，antd 已弃用该属性。
- **建议**：逐处改为 `<Space.Compact block><InputNumber /><Button disabled>单位</Button></Space.Compact>` 或 antd 推荐的替代形态。**涉及布局**，每处改完需对照前后截图（尤其窄屏 <640 的表现）。
- **预期效果**：设置页控制台告警清零；单位标注视觉不退化。
- **成本**：0.5～1 天（6 处 × 明暗 × 断点回归）。

### 低优先级（P2）——择期收尾

#### L1 · 平台账号卡片组件化（`AccountCard.tsx`，旧 P4-4）
- **问题**：上一轮唯一未做的计划项。账号区六份状态 + 8 个处理函数耦合在 `Settings.tsx`，且代码注释记录了多条历史缺陷（任何 `load()` 清空半成品输入、空串误删凭据）。**纯代码组织，零直接用户可见收益**。
- **建议**：按上轮报告 §6 的前置条件执行：**先补账号区测试网**（账号增删改 / Cookie 保存与清除），再抽取组件，保持 API 字段不变。若做了 H2 方案二（AI 表单拆子组件），可共享拆分手感。
- **预期效果**：设置页可维护性提升，账号区回归有测试兜底。
- **成本**：1～2 天（含测试网）。

#### L2 · 全站 `title` 属性换 antd `Tooltip`
- **问题**：见 V2。
- **建议**：全站扫 `title="`（排除 HTML 原生语义必需的场景，如表单原生校验提示），换 `Tooltip`。与 H3 中的会话行一起做掉大头，其余择期。
- **预期效果**：提示样式统一、键盘可达、即时显示。
- **成本**：0.5 天。

#### L3 · 文档同步（随手做）
- Plan §12.3 P9 行补「根因已定位：瞬时告警，非表单失效」结论；`responsive-breakpoints.md` §4.1 标注清理结果；本文档随批次更新状态。
- **成本**：0.5 小时。

   可拖拽分组行高由 40 → 50px，侧栏整体高度约 +100px（1200px 视口下 1077px，未溢出）。
   试过用 `margin: -5px 0` 把占位压回 40px，但那样**相邻两行排序按钮的命中区会重叠 8px**
   （点缝里可能误触上一行的「下移」），因而放弃 —— 宁可侧栏高一点，也不要会误触的目标。
2. **迷你会话浮层的排序按钮**：视觉上改成透明底 + 悬停显描边，命中区 24×24（原来 18×18）。
3. `.reorder-controls` 仍是 `opacity: 0` 隐藏（**不是** `visibility: hidden`）：
   Tab 焦点停靠点保留，键盘用户 Tab 到按钮时 `:focus-within` 让控件显形。
4. **本会话中 `Assistant.tsx` 被外部改动替换过一次**（14:03 的版本把会话行的
   ↑↓ / 重命名 / 置顶 / 删除 四个按钮换成了 `⋯ 会话操作` 下拉菜单，H3 的「显式重命名按钮」
   实现随之消失）。本次按**磁盘上的最新实现**为准重新验证并调整了 H3 断言：
   键盘路径改由该下拉菜单承担（Tab 可达、菜单项可激活），并保留了「会话标题不再用原生 `title`」
   这一项（V2 / L2 的一部分）。若后续还要补一个**行内常驻**的重命名按钮，请先确认该行的最终设计。
5. `InputNumber` 的单位块是 `disabled` 按钮，**不是**可点击控件；`.compact-unit` 的样式挂在
   `index.css` 的设置页段落里，换主题时跟随 `--text-3` / `--surface-2` / `--line` 三个 Token。
