# 赛时题分析设计

## 背景与目标

当前系统已有跨平台的已参赛比赛识别与复盘能力，但全局能力分析主要围绕日常提交和题目现有标签。用户希望单独分析比赛期间卡住的题目，把比赛提交与赛后补题区分开；新近比赛缺少平台标签时，允许用户为题目补充自己的赛时分析标签。赛时数据和标签不得写入或改变原有全局薄弱项、题目标签及知识点分析。

本功能同时把已参加比赛按是否产生 Rating 变化分类：Rated 正式参赛、非正式参赛。正式/非正式分类用于比赛列表筛选和赛时分析，不替代官方/虚拟参赛语境。

## 已确认的范围

- 赛时分析纳入官方比赛、虚拟赛和自我模拟比赛。
- 首版只纳入能可靠匹配到平台比赛和比赛窗口的提交。无法可靠匹配的提交不猜测归属、不纳入赛时统计。
- 按比赛窗口计算赛时状态。比赛期间至少提交过且窗口结束前没有通过的题目为“赛时未通过”。若该题在比赛结束后通过，显示为“赛后通过”，但赛时未通过状态不被覆盖。Codeforces 明确提供的 `contest` / `virtual` / `practice` context 优先用于区分赛时、虚拟赛和补题；其他平台使用准确的赛事时间窗。
- 赛时手动标签按用户、比赛、平台和题目编号隔离保存，仅用于赛时分析，不修改 `problems.tags`、知识点标注或现有日常分析。
- 不同平台中同编号的题目依平台 ID 区分。每道比赛题可添加多个用户标签，支持新增和移除。
- 比赛分类遵循平台提供的 Rating 变化记录：有比赛级 Rating 变化记录为 **Rated 正式参赛**；平台已确认比赛结束且无 Rating 变化为 **非正式参赛**；缺少或未同步到充分证据时为 **待确认**，不得把数据缺失解释为没有变化。
- 虚拟赛仍纳入赛时分析；Rated 分类独立于官方/虚拟语境。虚拟赛没有 Rating 变化记录时，按上述规则归类为非正式参赛（平台状态已确认后）。

## 方案选择

1. 在现有全局分析上增加赛时筛选。实现成本较低，但标签与统计仍与日常数据共用，隔离边界不清。
2. 新增独立赛时分析子系统（推荐）。使用现有比赛归属结果和提交记录，另建只服务此分析的用户标签存储及页面，明确避免污染既有分析。
3. 通过用户手动登记每场比赛和每次赛时提交实现跨平台覆盖。灵活但持续录入负担较大，不适合作为首版。

采用方案 2。复用当前比赛参与识别逻辑和平台提交数据，不重做赛事中心；针对首版尚不能可靠归属的记录，不提供自动猜测结果。

## 页面与交互

在“赛事”区域增加独立的“赛时分析”入口。页面至少提供：

- Rated 正式参赛、非正式参赛、待确认的分类筛选；平台和比赛筛选。
- 赛时通过、赛时未通过、赛时未通过但赛后通过等题目状态计数及题目列表。
- 对每题显示平台标识、平台题号、所属比赛、赛时结果、赛后补题结果和用户赛时标签。
- 在题目行内添加/移除一个或多个自定义标签；标签仅以当前比赛中的该题为作用范围。
- 对有赛时未通过题目的标签进行聚合，展示用户手动标记的赛时薄弱方向。未标记题目仍计入未标记数量，不根据现有全局标签自动填充。

分类变更或比赛数据同步后，页面重新根据最新可用数据计算；用户标签继续附着于稳定的比赛身份和平台题目身份，不附着于排序或展示索引。

## 数据来源与归属规则

- 提交来源为现有 `submissions` 记录，包括提交时间、结果和平台提供的 `context`。
- 比赛身份及窗口优先使用现有赛事中心的平台参赛记录、官方日程和平台提供的比赛上下文。当前参与识别逻辑覆盖 Codeforces、AtCoder、洛谷、计蒜客、QOJ、牛客；具体平台/记录只有在现有归属规则确认比赛身份和时间窗口时才可纳入。
- Codeforces 的 `contest` 和 `virtual` context 作为赛时证据；`practice` 明确排除在赛时提交之外，并用于统计补题。Codeforces 的明确 context 可在虚拟赛没有原比赛时间窗时区分赛时与补题。其他平台沿用现有比赛身份和准确窗口归属判断，不因题目 key 相同就认定为赛时提交。
- 赛时通过仅统计比赛窗口内的 Accepted；比赛结束后的 Accepted 独立记为赛后通过。
- 如比赛窗口、比赛身份或 Rating 变化状态证据不足，相关记录保留为未归属/待确认，不伪造分类或赛时结论。

## 数据隔离与边界

新增的赛时标签记录至少以用户 ID、比赛稳定 ID、平台 ID、平台题目 ID 和标签文本组成唯一作用范围。删除标签不影响平台题目或全局题库元数据。标签不会自动复制进 `problems.tags`，赛时聚合也不会写回日常能力值、知识点掌握度或原有弱项分析。

比赛分类是比赛级状态，来源于平台的 Rating 变化数据，不以提交结果、比赛分数推断 Rating 变化。数据源未返回可判断结果时展示“待确认”。

## 验收标准

1. 官方、虚拟和自我模拟比赛中，能可靠匹配比赛窗口的提交会进入赛时分析；日常练习及赛后补题不会被计为赛时提交。
2. 某题赛时未通过、赛后通过时，页面同时保留两个阶段的结果，赛后 Accepted 不会改写赛时结论。
3. 用户可以在赛时分析页对比赛题目添加和删除多个自定义标签；同一道题出现在不同比赛时，标签作用域相互独立。
4. 比赛期间题目没有平台标签时，用户仍可以添加自己的赛时标签；添加或删除标签不会改变题库标签或日常分析结果。
5. 存在比赛级 Rating 变化记录的比赛显示 Rated 正式参赛；已确认没有变化的比赛显示非正式参赛；数据不足时显示待确认。
6. 用户可以按比赛分类和平台筛选赛时分析，并查看用户标签对应的未通过题目统计。
7. 不可靠匹配的提交不会进入分析，也不会被误判为非正式比赛或赛时未通过。

## 不在首版范围

- 对无法可靠匹配的提交提供手动参赛登记或手动改判入口。
- 将赛时标签同步到题目全局标签、知识点系统或第三方平台。
- 基于官方标签自动补全用户赛时标签。
- 仅凭用户参赛行为或赛时提交表现推断 Rating 变化或正式参赛状态。
