# issue #67：ChatGPT 登录（Sign in with ChatGPT）调研结论

issue #67 希望在「设置 → AI 配置 → 模型提供商」里加「使用 ChatGPT 登录」，用 Plus/Pro 订阅额度。
**这一轮没有实现**，原因不在难度，而在两个硬约束。以下是核实过的事实与后续路线。

## 一、官方现状（2026-11 核实）

- ChatGPT plan usage 对**开源项目 / 本地个人项目**开放，新接入**不需要** client secret 或 partner key：
  动态注册（`client_id=dynamic_agent_client` + `agent_name_hint` + `ext_agent_host_id`）+ OAuth PKCE，
  授权在 `auth.openai.com`，回调打到 127.0.0.1 回环。
  <https://developers.openai.com/siwc/quickstart>
- 端点不是另一个 base_url：就是 `POST https://api.openai.com/v1/responses`，
  明确禁止指向 ChatGPT 的 `backend-api`。
  <https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference>
- 预览期硬约束：必须 `store:false` + `stream:true`；`input` 必须是数组；system 走 `instructions`；
  **禁止** `temperature` / `top_p` / `max_output_tokens` / `metadata` / `previous_response_id`；
  不支持 Files 上传、file search、hosted MCP。
  <https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations>
- 凭据形态：access_token 1 小时、refresh_token 30 天且每次刷新轮换；超额是**流内错误**
  （`response.failed` + `subscription_sharing_usage_limit_exceeded`）。
  <https://developers.openai.com/siwc/token-sharing-open-source/token-reference>
- 许可：官方 DevKit 是 Noncommercial License，本仓库是 GPL-3.0-only，**不能直接引入 `@siwc/*` 代码**，
  只能照公开文档自行实现 OAuth。

## 二、为什么现在不做

工作台当前的 AI 链路是 Chat Completions 语义，且**依赖了 siwc 预览期禁止的那些参数**：

- `temperature`（`provider.ts` 的 `chat()` / `chatStream()` 都发）；
- `max_tokens` 及其降级阶梯（聚合网关按 max_tokens 路由模型时的重试，`nextMaxTokensLimit`）；
- 非流式 `chat()`（标题生成、上下文摘要等走它，依赖 `choices[0]`）；
- Files 附件（`filesUrl` / `file_id` 内容块）。

也就是说「接订阅额度」不是加一个 provider，而是**整条链路换协议**：
`messages` → `input` 数组、`tool_calls`/`tool_call_id` → `function_call` item + `function_call_output`、
SSE 从 `choices[0].delta` 改为 `response.output_text.delta` 等事件分派、
截断续写从 `finish_reason === 'length'` 改为 `status` + `incomplete_details`。
更实际的风险是：即便做完了，预览期禁用 `temperature`/`max_tokens` 会让现有的参数调优与
截断续写全部失效 —— 换来的体验**不如**现在的 API Key 路径。

## 三、建议路线（已写进给 issue 的回复）

**第一步（可独立做，本身就有收益）**：给提供商加「Responses API 模式」开关
（`AiProviderConfig.protocol?: 'chat' | 'responses'`，缺省 `chat`），映射层留在 `provider.ts` 内部，
`ChatMessage` 抽象不变 → 路由与前端零改动。这既是 siwc 的**唯一前置**，
也顺带满足 OpenAI 官方推荐「新项目用 Responses」的现状，对用第三方中转站的用户同样适用。

**第二步（等官方放开预览期的参数限制后再评估）**：
OAuth PKCE 状态机 + 回环回调、按账户的 token 存储（现有 `apiKey` 是 DB 明文，级别不够，需要新表 + 加密）、
token 刷新任务、按账户的模型目录、`Using ChatGPT plan` 与 `Manage usage` 的 UI 规范。
