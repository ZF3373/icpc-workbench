# issue #67（续）：「本地 Codex」提供商 —— 经本机 Codex CLI 使用 ChatGPT 订阅额度

issue #67 评论区（fstyou）提出的替代方案已实现：在「设置 → AI 配置 → 模型提供商」新增
**「本地 Codex」**选项。选中后，工作台使用 AI 时不再直连 OpenAI 兼容 HTTP，而是调用本机
已安装并通过 `codex login` 登录 ChatGPT 的 **Codex CLI**（`codex exec --json` 子进程）。
登录与凭据刷新完全由 Codex 自身处理——工作台不存任何 ChatGPT 凭据，不触碰 token 刷新。

## 一、设计要点

- **提供商新增 `protocol` 字段**（`shared/src/aiProviders.ts`）：`AiProviderProtocol = 'chat' | 'codex'`，
  缺省 `'chat'`。这正是 2026-11-24 调研（`2026-11-24-issue67.md` 第三节）建议的
  「protocol 开关 + 映射层留在 provider.ts 内部」路线——只是第一个落地的取值不是
  `'responses'` 而是 `'codex'`（子进程方案绕开了 Responses API 预览期的全部参数禁令，
  因为协议由 codex CLI 自己去谈）。
- **分派在 `AiProvider` 内部**（`server/src/ai/provider.ts`）：`cfg.protocol === 'codex'`
  时 `chat()` / `chatStream()` 委托给 `server/src/ai/codexProvider.ts`，消息与回调签名
  完全不变——聊天、标题生成、上下文摘要、训练计划、题单 AI 等所有调用点**零改动**。
- **单轮状态化**：`codex exec` 是单次非交互调用，多轮对话由适配层把 `ChatMessage[]`
  组装成「系统指令 / 对话历史 / 当前问题」三段式说明文本，经 **stdin** 传入
  （不进命令行参数：Windows 有 ~32K 命令行长度限制，也避免 shell 回退时的注入面）。
- **能力差异（有意为之）**：`temperature` / `max_tokens` / OpenAI function calling 的
  `tools` 不透传（codex exec 无对应按次覆盖；工具由 codex 自带沙箱与 MCP 配置决定）；
  Files API 附件块（`file_id`）无法发送（占位说明）；`image_url` 的 data URL 会写成
  临时文件随 `-i` 附上，用完即删。
- **安全边界**：codex 以 `-s read-only`（只读沙箱）+ `--ephemeral`（不写会话文件）+
  `--skip-git-repo-check` 运行，工作目录是一次性 tmp 目录（不在工作台数据目录，避免
  codex 读到含明文密钥的 settings 存储）；模型名经白名单校验（`[A-Za-z0-9._/-]+`）
  才进 `-m`；prompt 永远走 stdin。

## 二、调用链

```
设置页（protocol='codex'）
  → aiConfigFromDb 透传 protocol（server/src/config.ts）
  → new AiProvider(cfg)（各调用点不变）
  → codexContentStream（server/src/ai/codexProvider.ts）
      spawn codex exec --json --ephemeral -s read-only [-m model] [-i img…] -C <tmpDir>
      stdin ← 三段式 prompt；stdout ← JSONL 事件流
      agent_message → content delta（兼容 item.updated 分段与 item.completed 整段）
      reasoning → onReasoning 回调；turn.completed.usage → onUsage（OpenAI 兼容映射）
      turn.failed / 空闲看门狗（120s）/ 调用方 abort → 可读错误
```

- **Windows 兼容**：npm 全局安装的 codex 是 `codex.cmd` shim，libuv 的 PATH 搜索只认
  `.exe`，直接 spawn 报 ENOENT —— 自动回退 `shell: true` 包装（cmd.exe 按 PATHEXT 解析）。
  事件监听在 spawn 返回后**同步**挂载并缓冲（`CodexTurnSpawn`），快速退出的子进程
  （未登录）不丢事件；终止时 Windows 用 `taskkill /T /F` 砍整棵进程树。
- **设置页**（`client/src/pages/settings/AiSettingsCard.tsx`）：codex 提供商不显示
  API 密钥/Base URL 输入（显示 `codex login` 指引），无模型目录/档位/网关拉取，
  只留一个可选的模型输入（留空 = 跟随 codex 自身配置）；「测试连接」走服务端探测：
  `codex --version` → `codex login status` → 最小 `codex exec` 实测对话。
- **Assistant 页**：codex 提供商跳过网关模型拉取，模型菜单显示「跟随本机 Codex CLI 配置」。

## 三、前提与限制

- 需要较新版本的 Codex CLI（`--json` / `--ephemeral` 事件流口径按 codex-cli 0.164 实测），
  安装后需在终端 `codex login` 完成 ChatGPT 授权。
- 额度、限流、错误文案由 Codex/上游决定，工作台原样透出（未登录会提示 `codex login`）。
- 与 HTTP 提供商可并存：随时用「当前使用」下拉切换，AI 请求按活跃提供商实时解析。
- issue #67 原始诉求（Sign in with ChatGPT OAuth 直连 Responses API）维持
  「等官方放开预览期参数限制后再评估」的结论，见 `2026-11-24-issue67.md`。
