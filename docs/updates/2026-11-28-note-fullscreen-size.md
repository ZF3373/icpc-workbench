# 笔记全屏阅读的尺寸与字号（issue #52 后续反馈）

上一轮把「全屏沉浸阅读」做成了铺满整个应用窗口，反馈是：

> 全屏查看有点大了（因为字体还是小的），感觉 80% 屏幕大小（或者设置可以自行调节界面和字体大小），
> 字体在全屏时扩大一点（类似 typora 默认的字体大小）的体验感更好

「自行调节界面和字体大小」这条本来就有（顶栏「界面缩放」+ 卡内「笔记文字」50%–200%，
Ctrl+滚轮可调，各自持久化），所以缺的是**默认值**：全屏该浮在屏幕中间而不是铺满，
正文字号该跟着屏幕一起变大而不是停在卡片那套 13px。

## 改动

- **全屏阅读改成约占视口 80% 的居中浮层**（原来是 100% 铺满）。
  比例只有一个真源：`index.css` 的 `--note-fs-ratio`，宽高各自乘它；
  `noteCardWidth(true)` 从 `var(--app-viewport-width)` 改成引用 `var(--note-fs-width)`，
  所以窄屏那一档只要在媒体查询里把比例放回 1，组件和 JS 都不用动。
  仍然是视口变量而不是 `100vw/100vh`：整页缩放（`--app-zoom`）后视口单位会溢出。
- 既然不再贴边，**描边与圆角留回来了**（原来为了铺满把 `border: none; border-radius: 0`）。
  正文四周空出一圈窗口底色，读起来才像"一张浮在上面的纸"，而不是页面本身变了。
  焦点、Esc 两层退出、切换形态时正文滚回顶部这些行为不变。
- **全屏态正文放大约 1.25 倍**（13px → ≈16px，即 Typora 的默认正文档位；
  h1 21 / h2 19 / h3 17.5 / 行内代码 15）。做法是新增 `--note-fs-font-scale`，
  只在 `.note-card-modal.is-fullscreen` 上赋值，原来那些字号规则统一乘上它：
  `[data-note-zoom] .markdown-body { font-size: calc(13px * var(--note-text-zoom, 1) * var(--note-fs-font-scale, 1)) }`。
  两个系数各管各的 —— 用户手动调的「笔记文字」比例不会被全屏覆盖掉，而是叠乘。
- 作用范围**只有全屏阅读**：写作弹窗（三栏工作台）仍然铺满，收进 80% 会把三栏挤窄；
  卡片态取默认系数 1，排版一字不变。

## 验证

- `client/test/noteView.test.ts` 新增 4 条：比例 0.8、宽高都由它推导、不出现 `100vw/100vh`、
  字号系数叠乘 `--note-text-zoom` 且只在 `.is-fullscreen` 声明一处、窄屏档位放回 1、
  写作弹窗不受影响（防外溢）。
- 门禁结果见本次提交的 `npm run typecheck` / `npm run lint` / `npm run check:tokens` / `npm test`。
