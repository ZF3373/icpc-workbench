## #68 隐藏未 AC 题目的算法标签与难度

两个**独立**开关（设置页 →「题目信息隐藏」），偏好存 localStorage，与编辑器缩进同款机制
（`client/src/problemVisibility.ts` + `useProblemVisibility`，跨标签页经 storage 事件同步）。

设计要点：

- 只作用于**尚未 AC** 的题。已经 AC 的题再看标签有助于复盘，藏起来反而是损失；
  「有没有 AC 过」由行数据判定（题目管理页用 `ac_count`，写题历史用 `acCount`），
  未知按「没 AC」处理 —— 宁可多藏一格，也不要在用户还没做过这道题时泄底。
- 被隐藏的格子显示虚线占位「已隐藏」而**不是消失**：整列消失会让人以为这一版把功能砍了。
  占位不挂真实值 tooltip —— 悬停即可看穿等于没设开关（`.hidden-cell`）；
  想看得回设置页显式关掉。
- 作用点：题目管理页的「难度」「标签」两列、写题历史的「难度」列。

## #69 单次提交的详情链接与源码

三层，严格按 issue 的三条要求落地：

1. **同步时落链接，不当场访问详情页**。`submissions.submission_url` 加列；
   各适配器在 normalize 时把链接算好（`adapters/submissionUrl.ts`）：
   只需提交号的（洛谷 / QOJ / VJudge / DashOJ / 代码源 / 牛客竞赛）走平台模板表，
   还需要 contestId 的（Codeforces / AtCoder）由适配器用自己的 contestId 算。
   算不出来就**留空**（计蒜客、牛客在线编程段、PTA、力扣）—— 死链比没有链接更糟。
2. **老行不必等下一次同步**：`/api/history` 返回时按 `(platform, external_id)` 现算补齐；
   同步路径另有 `backfillSubmissionUrl`，已知行再次出现时顺手写回。
3. **源码按需取并缓存**：`GET /api/submissions/:id/source`，首次访问提交详情页抓取、
   落 `submission_sources` 永久缓存（某次提交的源码不会变），之后直接读库。
   每平台有最小请求间隔（`SOURCE_FETCH_MIN_INTERVAL_MS`），超了回 429 + `Retry-After`；
   解析不出源码时回 422 并给出可读原因（登录墙 / 结构变化），不把站点导航当源码返回。

> 抓取源码这一步**没有**对每个平台做实测（各平台的 `<pre id>` / 内嵌 JSON 位置见
> `submissions/source.ts` 的文档注释，Codeforces 与 AtCoder 的形态是公认的），
> 解析不出来时接口会明确回 422 而不是静默失败——如果某平台一直 422，按那里的注释补一个分支即可。

## #70 按比赛与参赛阶段筛选提交

`/api/history/submissions` 新增 `contestKey` / `phase`(`during`|`after`|`all`) / `account`。
阶段判定的优先级（`history/contestScope.ts`）：

1. **平台自报语境**（`submissions.context`，目前只有 CF 下发 `contest`/`virtual`/`practice`）。
   虚拟赛必须靠这个：虚拟赛的提交时间落在「今天某个窗口」，用时间窗判会全盘判错。
2. **官方赛程时间窗**（`participated_contests` / 日历），且必须是**非近似**窗口；
   旧版用 Rating 结算时间推算的窗口不可靠，会把赛后补题算成赛时。

两个都拿不到时不猜：返回「全部」而不是空列表 —— 宁可多显示几条，也不要让用户以为筛选漏了。

入口两处：数据概览「写题历史」的筛选行（选定比赛后出现「赛时 / 赛后 / 全部」页签），
以及赛事中心「我参加的」每张卡片上的「查看提交」（跳 `/?contestKey=…`，落地自动展开写题历史并切到逐条视图）。

## #71 题目与比赛的独立笔记

与复习笔记的区别在**归属**：复习笔记挂在 `review_items` 上，移出队列就跟着没了；
这里的笔记挂在**题目身份**（`problems/identity.ts` 口径，洛谷 CF 镜像与原站是同一道题）
与**比赛 key**（`codeforces:1877`）上，与复习队列彻底解耦。

- 表：`problem_notes(user_id, identity)`、`contest_notes(user_id, contest_key)`；
  正文空 = 删除该行（不留空记录，避免「有笔记」角标误报）。
- REST：`GET/PUT /api/notes/problem/:platform/:problemKey` 与 `/contest/:contestKey`，
  另有 `POST /api/notes/summaries` 给列表页批量取摘要（只回有笔记的键）。
- MCP：`get_problem_notes` / `save_problem_notes` / `get_contest_notes` / `save_contest_notes`，
  对应 issue 里那个「AI 先查三天提交与参赛记录，再读题目与比赛笔记做总结」的用法。
- UI：题目管理页操作列、写题历史操作列的笔记按钮（有内容时带绿点），
  赛事中心参赛卡片的「笔记」；写作与阅读复用复习库那套 `NoteWriterModal` / `NoteCardModal`。

## 顺带修的两处

- `runtime.json`：SEA 核心启动后把实际监听端口写进数据目录（退出时删除）。
  外部 agent 的 MCP 配置只能写死一个地址，核心端口漂移后那个地址就是死的 —— 见 issue #66 的文档。
- MCP 并发闸门：同时最多 2 个 `tools/call`，超出回 503 + `Retry-After`。
  协议握手（initialize / tools/list）不限流：卡住它们会让客户端以为服务不存在。
  理由见 issue #66 —— 并发大查询会把事件循环占满，连桌面壳的健康探测都会超时。
