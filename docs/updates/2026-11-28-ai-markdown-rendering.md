# AI 输出渲染：五处真实会踩的形态（issue #18）

issue #18 是「AI 助手的输出格式渲染问题，当前渲染逻辑还不够完善，欢迎 PR 或提供建议」。
这条太宽，没法直接动手，所以先把「模型真会写出来、而当前渲染确实不对」的形态逐个复现，
再一处处修。复现方式：`client/test/renderCheck.mjs` 的静态渲染管线（react-dom/server，
不需要浏览器）+ 对 `preprocessMath` / `repairStreamingMarkdown` 的直接断言。

修完之后仍然**没有覆盖全部渲染问题**：`上文\n---\n下文` 被渲染成 `<h2>`、纯英文写的
`costs $5 and $6` 仍然会被夹成公式，这两条是有意不做的，理由写在下面。

## 修了什么

### 1. 三级嵌套列表被吃掉第三级

`- a / ·· - b / ···· - c` 渲染成一句 `- b - c`，第三级整体消失。
根因不在列表处理，而在公式管线：`markdownMath.ts` 的 `CONTINUATION_START` 里含 `-` `*` `+`，
于是缩进 4 格以上的子列表被当成「上一条式子的续写」拼到父项行尾。
修法是给这条判据加一条前置排除：**上一行本身是列表项、且这一段也以列表标记开头**时，
这是 Markdown 的嵌套结构，原样交回解析器。只认这一种上下文，所以
`= max(0, upper_bound(…))` 那种真正的续行照旧回接（`markdownMath.test.ts` 早就钉着那条）。

### 2. 列表项下顶格的代码围栏把列表切成两截

`1. 建栈` + 顶格 ` ```cpp ` 是最常见的一种写法。按 CommonMark 顶格围栏**不属于**列表项，
于是代码卡贴到左边界（丢掉列表的悬挂缩进），后面的 `2. 弹栈` 另起一个 `<ol start="2">`。
新增 `client/src/components/markdownList.ts` 的 `indentFencesInLists()`：只认「上一行就是列表项」
这一种紧邻关系，把围栏**整段**（开栏 / 内容 / 收尾）补到该项的内容列。
CommonMark 会按开栏缩进量统一剥掉，代码里的相对缩进、高亮、复制出来的文本都不变。
未闭合的围栏（正在打字）也从开栏补到文末，避免出现「打字时贴边、写完又缩回去」的跳动。

一个必要的细节：必须逐段跳过**所有**围栏，不能只看「列表项的下一行」。
代码内容里以 `+ (` 开头的续行（`         + (i != k-i ? …)`）长得和列表项一模一样，
不跳完整段就会把真正的收尾围栏当成新开的围栏，从此后面全部错乱 —— 这条是写完第一版
被 `renderCheck.mjs` 里「用户截图 3」那个用例抓出来的。

### 3. 两句中文金额被夹成一条公式

`总花费 $1,000 元，约 $500 美元` → `$` 消失、「元，约」被排成斜体公式。
流式路径本来就有 `looksLikeMathTail` 挡这件事，但它只管**未闭合**的单个 `$`；
两个金额一起出现时是「已闭合」的合法配对，那道闸根本不会触发。
新增 `escapeCurrencyDollars()`（`preprocessMath` 的最后一步），判据三条都要满足：
开栏 `$` 后**直接跟数字**、到下一个 `$`（或行尾）之间**出现中文**、这段**没有数学特征**
（`\命令` / `_ ^ { }` / 关系符 / `=+*`）。于是同一段里各归各：
`$5 元` 转义成字面量，`$O(n)$`、`$10^9+7$`、`$f_i$`、`$[l, r]$` 完全不动。
纯英文的 `costs $5 and $6` 仍然会被夹 —— 少了中文这个信号就没有可靠判据，宁可不猜。

### 4. 行内代码里的 `$` 把代码本身改坏了

`成本写作 \`cost = $5 and $6\` 的形式` 渲染出来反引号没了，内容变成
`cost = $5 \operatorname{and} $6` —— 一个 `<code>` 变成了一串带 LaTeX 命令的公式源码。
两处叠出来的：
- `protectInlineCode` 对「span 内部分带 `$`」的分支只把内容原样放出、白丢掉反引号
  （完整的 `$…$` 那一支是保住的，半截的没保）；改成同样保持代码外观。
- `normalizeMathSymbols` / `enhanceMathLayoutInText` 跑在管线**末尾**，那时代码区早就
  还原回正文了，而它们只看 `$` 配对。新增 `hideDollarsInCode()`：按代码区分段，
  把代码里的 `$` 临时换成 U+0001，切完公式区再还原。

### 5. 半截表格分隔行的那一帧全是字面竖线

`| a | b |` 之后正打到 `| ---` 时整张表退化成正文，而且这段时间和打字一样长。
`repairStreamingMarkdown` 新增一步：按**表头行的列数**把这一行补成完整分隔行，
表格立刻以「只有表头」的形态出现，后续帧列数一致所以不会横向跳动。

### 6. 长回答的段落之间没有间距

流式增量渲染会把一条回答拆成两个 `.markdown-body`（已写定的前段 + 还在增长的尾段），
而 CSS 把每个容器的首子元素上边距和尾子元素下边距都清零 —— 接缝处变成 **0px**，
回答超过约 660 字后段落突然挤在一起。补一条 `.markdown-body + .markdown-body { margin-top: 10px }`，
与 `.markdown-body p` 的段间距同值。

## 有意没做的

- **`上文\n---\n下文` 被渲染成 `<h2>`**：这是 Setext 标题的合法语义（GitHub 也这么渲染），
  而「AI 想写分隔线」和「作者真的写了 Setext 标题」在文本上长得一模一样，无法区分。
  真要改只能一刀切禁用 Setext，代价是别人的合法标题也一起没了。先记在这里。
- **`20~25` 这类词内单波浪线**：实测 remark-gfm 的 `singleTilde` 默认关闭，非流式路径
  并不会把它排成删除线，不存在这个 bug（流式路径的 `escapeWordTildes` 照旧无害）。
